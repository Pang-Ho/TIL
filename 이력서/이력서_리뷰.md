## 총평 (한 줄 요약)

> **"SI 출신 치고 구조·리드 경험은 탄탄한데, 문장의 30%가 AI 냄새로 신뢰를 깎아먹고, 정작 'FE 전문성'을 증명할 성능·테스트 지표가 비어 있다."**

현재 상태는 **중상위권 서류**. 하지만 상위권 FE 포지션(네이버/토스/당근 급)에서는 **"애매하게 거르는" 3순위 이력서**로 밀릴 위험이 크다. 이유 3가지:

1. **AI가 다듬은 티가 나는 자기소개** → 요즘 리크루터는 이걸 보면 나머지 내용의 진위까지 의심한다. 킬 시그널.
2. **FE 핵심 역량 지표(렌더링/번들/Lighthouse/테스트)가 사실상 0** → "프론트 잘하는 사람"이 아니라 "SI 화면 만드는 사람"으로 읽힐 수 있음.
3. **백엔드·인프라 비중이 과함** → 차별점이 될 수도 있지만, 순수 FE 포지션에선 "포커스 흐린 잡부"로 역효과.

**살릴 강점:** PSR(Problem-Solution-Result) 구조, "14회→1회", "30s→1s", "개발 리더" 반복, "React 경험 없는 팀 리드" 서사 — SI 이력서 중 상위 20%.

## 관점 1. AI 대필 냄새 나는 문장 적발 🚩

가장 심각한 영역. "사람이 고민해서 쓴 게 아니라 AI가 매끄럽게 뽑아준 문장"으로 읽히는 구간.

### ❌ 최악 1 — 자기소개 리드
> "효율적인 개발 방식을 가장 중요하게 생각합니다. … 시간을 아끼는 **효율적인** 방향을 추구합니다."

- **문제:** 한 문단에 "효율"이 3번. AI가 키워드를 붙잡고 뱅뱅 도는 전형적 패턴. 정보량 0인 슬로건.
- **대안:**
  > "반복되는 코드와 불편한 UX를 그냥 못 넘깁니다. 검토·결재 로직이 화면마다 흩어져 있던 걸 커스텀 훅 하나로 모듈화해 유사 업무 개발 공수를 절반으로 줄인 경험처럼, 구조를 한 번 정리해 팀 전체의 시간을 아끼는 일에서 성취를 느낍니다."

### ❌ 최악 2 — "시스템 전체 관점"
> "시스템 전체 관점에서 문제를 바라보고 해결하는 역량을 갖추고 있습니다."

- **문제:** AI 자기소개 생성기에 넣으면 90% 확률로 나오는 문장. "~역량을 갖추고 있습니다"는 자가 진단 + 근거 제로 조합.
- **대안:** "역량을 갖췄다"고 말하지 말고 증거로 보여줘라.
  > "버튼 권한을 프론트 Wrapper 컴포넌트와 서버 AOP 양쪽에서 이중 검증하도록 설계한 것처럼, 프론트·백엔드에 걸친 문제를 한쪽에 떠넘기지 않고 양단에서 함께 풉니다."

### ❌ 최악 3 — 헤더 인트로
> "**재사용 가능한 구조와 개발 표준으로 팀의 개발 속도를 끌어올리는** 5년차 프론트엔드 개발자입니다."

- **문제:** 광고 카피 톤. "끌어올리는"이 정량 없이 붕 뜸.
- **대안:**
  > "React 기반 LG 계열사 SI 프로젝트에서 프론트엔드 개발 표준을 설계하고, 5개 프로젝트를 **개발 리더**로 이끈 5년차 개발자입니다."

### ❌ 기타 상투어 (정량/근거 없는 마무리)

| 문장 | 진단 |
|---|---|
| "지속적으로 실험하고 검증하고 있습니다" | 뭘 실험? 결과는? 공허함 |
| "업무 가시성과 **사용자 만족도 향상**" | 만족도 측정했나? 안 했으면 거짓말로 읽힘 |
| "협업 효율을 **크게** 높임" | "크게" = 정량 회피 신호 |
| "보안을 **강화**" | 추상어. "무엇을 어떻게" 없음 |

> **핵심 조언:** "향상 · 강화 · 극대화 · 효율적인 · 지속적으로 · ~역량을 갖추고" — 이 6개 단어가 나오면 그 문장은 다시 써라. 전부 측정 불가능한 형용사고, 리크루터는 이걸 "내용 없음"으로 번역해 읽는다.

## 관점 2. 프로젝트 기술 깊이 평가

PSR 구조는 좋으나 깊이 편차가 크다.

### 🟢 잘 쓴 것 — 프로젝트 2 (과제 관리 시스템)
"14개 항목 건별 저장 → 상위 컴포넌트 통합 관리 → **14회→1회**, 공수 50% 절감." 배경-원인-해결-수치가 논리적으로 이어짐. **이게 다른 프로젝트의 표준이 돼야 함.**

### 🔴 문제 1 — 프로젝트 1이 3개 이야기를 욱여넣음
- Presigned URL 이미지 로딩 + Fuse.js 검색 + Jenkins 빌드 메모리 — 무관한 사건 3개가 한 카드에 뭉쳐 초점이 흐려짐.
- **제목("개발 표준 프레임워크 운영·고도화")과 내용(특정 기능 3개)이 따로 논다.**
- Fuse.js 검색에 성능 수치 없음. 이미지 API 감소 수치 없음. 무한 스크롤인데 **가상화(virtualization/windowing)** 언급이 없음 → 오히려 구멍.

### 🔴 문제 2 — "서버 비용 30% 증가를 방지" = 최악의 지표
- **"방지"는 실적 지표가 아니라 가정법.** 검증 불가능한 상상 수치로 읽힌다.
- 진짜 스토리가 "빌드 메모리 급증으로 상위 인스턴스 증설(월 비용 +30%)이 예정됐는데 번들 Lazy Loading으로 취소시켰다"라면, **그렇게 사실대로** 써라.

### 🔴 문제 3 — 나머지 Result가 정성적으로 끝남
- 프로젝트 4(매뉴얼): "네비게이션 속도를 향상" → 몇 %? 반복 호출 몇 회 제거?
- 프로젝트 5(보험관리): "일관성 향상, 오류 감소, 효율 높임" 전부 형용사 → "롤백/재작업 빈도 감소", "develop 직접 push 사고 0건" 같은 관찰 가능한 결과로.

### 🔴 문제 4 — "단순 기능 구현 나열"로 읽히는 스택 설명
- "커스텀 컴포넌트 제작(Chip/ChipGroup, 메가 메뉴 등)"은 만들었다는 사실 나열. **왜 직접 만들었는지(접근성? 디자인 시스템 일관성?)** 한 조각이라도 있어야 깊이가 생김.

## 관점 3. 부족하거나 아쉬운 내용

**FE 지원자인데 FE 핵심 증거가 빈다. 가장 치명적.**

1. **성능 최적화 정량 지표 = 사실상 0**
   - Lighthouse, LCP/CLS/TBT, 번들 사이즈, 코드 스플리팅, 이미지 최적화 수치 — 하나도 없음.
   - 유일한 성능 숫자 "30s→1s"는 **번역 솔루션 API = 백엔드 개선**. FE 성능이 아님.
   - 사이드 프로젝트(Next.js/CloudFront)는 Lighthouse 돌리기 딱 좋은데 점수 한 줄이 없음. **지금 당장 측정해서 넣어라. 30분이면 됨.**

2. **테스트 코드 = 전무**
   - Jest/Vitest/RTL/Playwright/Cypress 어디에도 없음. Storybook만 있음.
   - "개발 표준 정립"한 5년차인데 테스트 전략이 표준에 없다 = 큰 구멍. **면접에서 반드시 찔린다.**

3. **Next.js App Router 숙련도(4/5)가 과장으로 보임**
   - 실무 5개 중 4개가 Vite 기반 SPA, App Router는 사이드 프로젝트 1개뿐.
   - RSC/서버액션 질문에 4/5 자신감 대비 대답이 얕을 위험 → 3으로 낮추거나 실제 사용 근거 명시.

4. **자가 별점 5/5(React·TS·React Query)는 오히려 감점**
   - 5년차가 스스로 만점 → "자기 객관화 안 되나?"로 읽힘. **최고 등급은 4가 안전.** 별점 자체를 없애는 이력서도 많다.

5. **상태 관리 라이브러리 "선택 이유"가 없음**
   - Zustand vs Redux vs Jotai, React Query 도입 근거 — "왜 골랐나" 한 줄이 있어야 "트렌드만 따라간 게 아니라 판단했다"가 증명됨.

## 관점 4. 종합 Worst 요소 & 레이아웃

- **자기소개가 너무 길고 추상적:** 리드 1개 + 본문 3문단 전부 "성향 선언". 각 문단 첫 문장에 사실/수치를 박아라.
- **`.about-highlights` CSS를 만들어놓고 안 씀:** 3칸 핵심 지표 카드 스타일이 정의돼 있는데 미사용. 눈에 꽂히는 숫자 3개를 넣으면 스캔 3초 만에 임팩트 전달. (→ v2에서 반영)
- **타임라인 겹침이 혼란:** 프로젝트 1(2026.01~현재), 2(2025.06~09), 미니리스트 "개발 표준 시스템 운영 2025.01~12"가 겹쳐 "동시에 이걸 다 했다고?" 의문. 병행 표기하거나 묶어라.
- **자잘한 오타/표기 불일치:** "결재•검토", "개발•고도화" 가운뎃점(•) 사용, "심사 기준을 결정 했습니다" 띄어쓰기 오류. **이력서 오타 = 꼼꼼하지 않다의 증거.**
- **"5년차" vs 실제:** 2022.07 입사 → 2026.07은 만 4년. 틀린 건 아니지만 계산 빠른 면접관은 갸우뚱할 수 있음.
- **백엔드/인프라 스택이 FE 이력서의 1/4 차지:** 순수 FE 포지션 지원 시 "Also worked with"로 격하해 FE 밀도를 높여라.
